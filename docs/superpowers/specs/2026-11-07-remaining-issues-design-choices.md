# 남은 설계 선택 4건

상태: 사용자 `진행`으로 4건 모두 권장안 승인. 검토에서 같은 안전 조건의 누락이 두 번 확인된 부분만 중지했다.
근거는 AGENTS.md의 “같은 불변식에서 리뷰가 두 번 이상 구멍을 내면 패치를 이어 가지 말고
설계 분기를 사용자에게 올린다” 규칙이다. 이미 승인된 일반 진행을 다시 묻는 것이 아니라,
아래 구체적인 설계 변경을 선택한다.

1. **#196 배포 기록 정리:** 원본을 바꾸기 전에 검증된 복구 복사본을 디스크에 보존한다.
   최대 64 MiB의 일시적 추가 공간을 사용한다. [설계와 반례](2026-11-07-runtime-prune-crash-recovery-amendment.md).
2. **#220 작업본 정리:** 파일을 한 번 열어 검증한 핸들을 정리 직전까지 유지하고, 검증 후
   다시 여는 틈을 없앤다. [설계와 반례](2026-11-07-cleanup-artifact-handle-amendment.md).
3. **#195 관찰 기록:** 별도 프로세스 잠금 안에서 같은 FD로 로그 형식을 검증하고 완전한 기록을
   확인한 뒤 실행을 허용한다. 손상 시 자동 수리하지 않고 차단한다.
   [설계와 반례](2026-11-07-observe-audit-framing-amendment.md).
4. **#195 설치 복구:** 중단 후 파일과 디렉터리의 fsync 의무를 다시 수행하고, 중간 hardlink의
   귀속과 완료 상태를 재검증한다. [설계와 반례](2026-11-07-guard-restore-durability-amendment.md).

**권장 선택은 4건 모두 적용**이다. 사용자 목표인 남은 이슈를 모두 처리한 뒤 한 번 배포하는
범위를 유지한다. 이번 선택은 로컬 설계·구현·검증만 허용한다. 기존의 push·PR·머지·운영 배포·
프로세스 종료·실제 기록/작업본 삭제는 포함하지 않는다. Task/Claim이나 Registry cutover도 없다.

다른 선택은 해당 기능을 이번 배포에서 보류하는 것이다. 이때 #196 또는 #220, #195는 완료로
표시하지 않으며 검증된 다른 변경만 배포 준비한다. 원하는 항목만 번호로 따로 선택할 수도 있다.

현재 보존한 완료분은 #206/#217의 로컬 커밋 146cd19와 #201의 로컬 커밋 bfba78f다.
3건은 아직 원격 반영하거나 배포하지 않았다. 나머지 구현 초안과 테스트·검토 기록은 별도
작업본에 보존했다. 전체 테스트 통과 수를 위 안전성 결함의 해소로 사용하지 않는다.
